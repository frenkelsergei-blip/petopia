# PETOPIA workspace rules

- This is the independent PETOPIA game. Do not use Waypoint or its files, tools or workflows.
- Plan of record: `docs/roadmap.json` (phases from the V2 GDD). Rebuild `docs/roadmap.html` with `python3 tools/build_roadmap.py` and republish the roadmap artifact (https://claude.ai/artifact/JVPhdm31cGyxefmyaikMZ5) when tasks change. Every new user request becomes a task in its phase and a row in the requests log. Work phases in order.
- The user's direct instructions govern scope. Preserve the original GDD under `docs/sources/`; record changes in `docs/design-amendments.md` rather than silently rewriting source material.
- Read `docs/progress.json`, `docs/design-amendments.md` and `docs/change-log.md` before continuing project work. Distinguish user decisions, provisional prototype choices, implemented behavior and open playtest feedback.
- For each playable iteration, update code/data and save validation together, run relevant checks, update `docs/verification.json`, the change log and progress source, then rebuild `docs/progress.html` with `python3 tools/build_progress.py` before reporting completion. Do not mark a phase outcome complete from code or concepts alone.
- Visual source of truth: only `assets/concepts/current/` (see its README). The A49 UI kit governs all UI styling; current V01–V09 screens govern content and composition, particularly V02 gameplay. Never use `assets/concepts/archive/` as a reference. Follow docs/art-production-matrix.md before generating assets. Review at actual camera scale with child/pet present; do not treat isolated generated illustrations as finished game assets. Keep hero approximately 18–23% of playfield height, organic bank/ledge shapes, grounded scenery and a proportional home garden. New visual revisions need review; tests do not imply art approval.
- The concept is a quality, identity and depth benchmark, not an exact level layout to copy or a flat illustration to substitute for playable world construction. V2 runtime art was rejected. See `docs/art-rejection-audit.md`; do not describe the rejected result as accepted or close based on tests or scale alone.
- Keep new assets and their provenance, prompts, frame regions, pivots and completion state in the workspace and `docs/asset-register.json`. Concept approval is not approval of a complete production animation set.
- Mobile-first portrait is the primary play layout. Keep touch targets at least 48 logical pixels, safe areas, simultaneous movement/action input and saved size/spacing/height settings; preserve keyboard desktop testing and in-place resize. Do not defer mobile interaction until final art.
- The child is the controlled character. Foxy follows and performs requested cooperative actions; fetch input throws as the child, while pet catch/return is automatic.
- Preserve a starter-accessible main route. Reusable tools and species abilities may create alternate routes; missing tools must not trap the player. Normal recovery must preserve durable rewards, ownership and progress.
- Reuse the canonical coin and shared UI helpers across every screen. Keep art and graybox rendering on the same physics, level data and save systems.
- Routine saves use a single ordered background writer with a bounded latest-snapshot queue. Purchases and completion rewards publish only after durable transactions. Preserve the slow-disk, duplicate-reward and shutdown checks when changing persistence.
- `python3 tools/run_checks.py` runs the current suites. Actual scene captures use `tools/capture_graybox.gd`; the headed frame-time sample uses `tools/profile_gameplay.gd`. Record sample scope and remaining manual/device checks honestly.
